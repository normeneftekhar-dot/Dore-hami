# کسی اینجاست؟ — نسخه Vercel + GitHub + Upstash

این بسته، نسخه بازطراحی‌شده برای استقرار روی Vercel است. رابط اصلی و طراحی اتاق از نسخه ارسالی حفظ شده و لایه ارتباط چندکاربره به WebSocket روی Vercel Functions منتقل شده است.

## معماری

- `public/index.html`: رابط اصلی سایت
- `public/room-shim.js`: اتصال مرورگر به WebSocket با مسیر `/api/ws`
- `api/ws.js`: WebSocket Function؛ مدیریت اتاق عمومی و خصوصی
- `api/chat.js`: واسط امن گفت‌وگوی NPCها؛ کلید AI فقط در متغیر محیطی سرور است
- `Upstash Redis`: وضعیت موقت حضور و Pub/Sub برای انتقال رویدادها میان نمونه‌های مختلف Vercel
- `vercel.json`: تنظیمات Function و هدرهای امنیتی

Vercel اتصال WebSocket را می‌پذیرد، اما اتصال‌ها ممکن است به Function instanceهای مختلف برسند. به همین دلیل، وضعیت اتاق و رویدادها نباید فقط در حافظه یک نمونه باشند. این نسخه وضعیت حضور را در Redis نگه می‌دارد و رویدادها را با Pub/Sub میان نمونه‌ها پخش می‌کند.

## استقرار از GitHub تا Vercel

### ۱. ساخت مخزن GitHub

1. وارد https://github.com شو.
2. یک Repository جدید با نام `kasi-injast` بساز.
3. برای آزمایش می‌توانی Repository را Private نگه داری؛ عمومی‌کردن مخزن برای کارکرد سایت لازم نیست.
4. محتویات همین پوشه را در ریشه مخزن بارگذاری کن؛ یعنی پوشه‌های `api` و `public` و فایل‌های `package.json` و `vercel.json` در ریشه باشند، نه اینکه کل پوشه پروژه یک لایه دیگر تو‌در‌تو قرار بگیرد.

### ۲. اتصال مخزن به Vercel

1. وارد https://vercel.com شو و با GitHub وارد شو.
2. از `Add New` گزینه `Project` را انتخاب کن.
3. مخزن `kasi-injast` را Import کن.
4. Framework Preset را روی `Other` بگذار؛ Build Command و Output Directory لازم نیست.
5. Deploy را بزن. در این مرحله صفحه ممکن است بالا بیاید، اما تا اتصال Redis، اتاق مشترک فعال نخواهد شد.

### ۳. ساخت Redis در Upstash

1. وارد https://upstash.com شو و یک دیتابیس Redis بساز.
2. منطقه جغرافیایی نزدیک به منطقه Function سایت را انتخاب کن تا تأخیر کمتر شود.
3. از بخش اتصال، آدرس TCP/Redis را بردار. باید شبیه `rediss://default:...@...upstash.io:6379` باشد. آدرس REST به‌تنهایی برای این نسخه کافی نیست.
4. در Vercel به Project Settings → Environment Variables برو.
5. متغیر `REDIS_URL` را با آدرس کامل Redis ثبت کن و برای Production و Preview فعالش کن.
6. بعد از ذخیره متغیر، حتماً یک Redeploy انجام بده.

نکته: این پروژه از `ioredis` و اتصال Redis با پروتکل TCP/TLS استفاده می‌کند؛ `UPSTASH_REDIS_REST_URL` و `UPSTASH_REDIS_REST_TOKEN` جایگزین `REDIS_URL` نیستند، مگر اینکه کد برای REST بازنویسی شود.

### ۴. فعال‌کردن NPCهای هوش مصنوعی (اختیاری)

در Vercel → Project Settings → Environment Variables:

- `OPENAI_API_KEY`: کلید API
- `OPENAI_MODEL`: مدل در دسترس حساب، مثلاً `gpt-4o-mini`
- `OPENAI_BASE_URL`: فقط در صورت استفاده از endpoint سازگار و سفارشی

سپس Redeploy کن. بدون این متغیرها، اتاق چندنفره همچنان می‌تواند کار کند؛ فقط مکالمه با NPCهای هوش مصنوعی غیرفعال می‌ماند.

## اجرای محلی

نیازمند Node.js 20 یا بالاتر و یک Redis قابل دسترس است:

```bash
npm install
npx vercel dev
```

برای اجرای محلی، `REDIS_URL` و در صورت نیاز متغیرهای AI را در محیط سیستم یا فایل `.env` محلی قرار بده. فایل `.env` را هرگز به GitHub نفرست.

## مسیرهای مهم

- صفحه: `/`
- فایل آداپتور: `/room-shim.js`
- WebSocket: `/api/ws`
- بررسی اتصال Redis: `/api/health`
- API هوش مصنوعی: `/api/chat`

## رفتار حریم خصوصی و نگهداری داده

- پیام‌های عمومی و خصوصی در این پیاده‌سازی آرشیو نمی‌شوند؛ برای رساندن آن‌ها به کاربران متصل، از Redis Pub/Sub استفاده می‌شود.
- وضعیت حضور و داده‌های مکانی/تعامل کاربر در Redis موقتاً نگهداری می‌شود. هر اتصال TTL دارد و کلیدهای اتاق نیز زمان انقضا دارند؛ خروج عادی، داده همان اتصال را حذف می‌کند.
- در صورت قطع ناگهانی Function، داده‌های حضور با TTL منقضی می‌شوند؛ حذف آنی در قطع ناگهانی تضمین‌شدنی نیست.
- سرویس Vercel و Upstash ممکن است لاگ‌های فنی مستقل از برنامه داشته باشند.
- اگر گفت‌وگوی AI فعال شود، prompt و محتوای همان مکالمه برای دریافت پاسخ به ارائه‌دهنده AI ارسال می‌شود؛ سیاست نگهداری آن تابع ارائه‌دهنده است.

## محدودیت‌ها و مواردی که باید قبل از انتشار عمومی تست شوند

1. در Vercel، WebSocket با رسیدن Function به حداکثر زمان اجرا بسته می‌شود؛ آداپتور مرورگر اتصال مجدد و ورود دوباره به اتاق را انجام می‌دهد. مدت دقیق به پلن و تنظیمات Function بستگی دارد.
2. Pub/Sub پیام را برای مشترکانی که در لحظه آنلاین نیستند نگه نمی‌دارد؛ این رفتار عمدی است و برای این اتاقِ زنده مناسب‌تر از آرشیو پیام است.
3. ورود مهمان بدون حساب کاربری است. کد اتاق خصوصی تصادفی است، اما احراز هویت هویتی یا سیستم گزارش/مسدودسازی سوءاستفاده در این نسخه وجود ندارد.
4. محدودیت ۸۰ نفر برای اتاق عمومی و ۲ نفر برای اتاق خصوصی در کد اعمال شده است. این سقف ظرفیت تضمین عملکرد در بار بالا نیست.
5. محدودیت نرخ API هوش مصنوعی در حافظه هر Function است، نه یک سهمیه سراسری دقیق. برای انتشار عمومی، بهتر است سقف مصرف در ارائه‌دهنده AI و Rate Limit سراسری در Redis نیز تنظیم شود.
6. قبل از اعلام عمومی، دو یا چند دستگاه را هم‌زمان تست کن، مخصوصاً پیام عمومی، تغییر موقعیت، دعوت خصوصی، رد دعوت، خروج، قطع اینترنت و اتصال مجدد.
7. این بسته از نظر نحوی بررسی شده، اما تا وقتی در حساب واقعی Vercel و Upstash مستقر و با چند مرورگر تست نشود، نمی‌توان ادعای تست انتها‌به‌انتها یا آمادگی تولید داد.

## امنیت مخزن

- کلید AI، آدرس Redis و رمز آن را در فایل‌ها یا commitهای GitHub قرار نده.
- اگر کلیدی اشتباهاً وارد مخزن شد، صرفاً حذف فایل کافی نیست؛ کلید را در سرویس مربوطه rotate کن.
- برای آزمایش اولیه، Repository خصوصی و Deployment Preview خصوصی/محافظت‌شده انتخاب امن‌تری است.
